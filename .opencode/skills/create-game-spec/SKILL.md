# Create Game Spec

## Choose the smallest useful format

- Use a quick spec for one focused behavior.
- Use a gameplay spec for a mechanic or repeated player action.
- Use a UI spec for screens, navigation, or HUD behavior.
- Use a level spec for player goals, pacing, and challenges.
- Use a technical spec for cross-cutting or risky technical decisions.

## Procedure

1. Read the vertical slice contract and relevant project files.
2. State the player objective and explicit exclusions.
3. Use a template in `docs/templates/`.
4. Write testable acceptance criteria and manual tests.
5. Record unanswered questions instead of inventing rules.
6. Suggest small tasks across design, programming, assets, and QA only when necessary.

## Rule

Do not require a spec for typo fixes, a single value adjustment, or other trivial changes.
