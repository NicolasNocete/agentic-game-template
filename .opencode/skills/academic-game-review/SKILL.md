# Academic Game Review

## Review modes

- `code`: clarity, duplication, coupling, configurable values, state handling, and testability.
- `design`: core loop, player objective, decisions, feedback, difficulty, and scope.
- `ux`: controls, visible state, feedback, navigation, recovery from errors, and readability.
- `accessibility`: alternatives to color-only feedback, text readability, controls, pause, and remapping opportunities.
- `delivery`: README, execution, credits, licenses, playtests, AI record, and known issues.

## Procedure

1. Read the manifest, vertical slice contract, relevant spec, and target files.
2. Report only evidence-based findings.
3. Order findings by severity: blocking, important, improvement.
4. For each finding state location, risk, recommendation, and verification step.
5. Cite a relevant public source only when it strengthens a meaningful recommendation.

## References

## Rule

Heuristics are guides, not universal laws. User playtests can confirm or reject a review hypothesis.
